# Продолжение разработки

1. Прочитай `docs/PLAN.md` и `docs/PROGRESS.md`, затем проверь `git status`.
2. Сохраняй пользовательские документы и незнакомые изменения. Не коммить секреты.
3. Выбирай следующий незавершённый этап P00–P14. Не выдавай заглушку за проверенную интеграцию.
4. После работы обновляй PROGRESS: файлы, проверки, ограничения, следующий конкретный шаг.
5. Основной стек: .NET 8, PostgreSQL, React 19 + Vite. Исходники интерфейса в frontend, сборка в src/GigaTodo/wwwroot. Внешние сервисы доступны агентам через их инструменты; не добавляй интеграции в backend.
6. Очередь выбирается сверху вниз; незавершённые зависимости пропускаются. Суммарно не более Runtime__MaxConcurrentAgents активных запусков (1–100, по умолчанию 10) на всех досках, включая критиков; внутренние субагенты не учитываются. Пользователь не меняет стадии произвольно. Изменения состояния защищаются транзакциями PostgreSQL.
7. Запускай проверки из README. Для реальных интеграций нужны установленный Gigacode и пользовательская конфигурация; их отсутствие записывай явно.
8. Jira Story → feature/KEY-123, Bug → bugfix/KEY-123: фактический тип проверяет агент своими инструментами. Переименовывать только ветку назначенного worktree; при коллизии имени или неясном типе требуется уточнение.
9. Вложения хранятся вне Git в Runtime:Root/attachments; метаданные в PostgreSQL. Не удаляй общий оригинал при удалении связи с задачей. При распаковке проверяй пути/ссылки/лимиты; файлы не исполняются. Новые вложения должны привязываться до назначения запуска, изменения активного набора запрещены.
