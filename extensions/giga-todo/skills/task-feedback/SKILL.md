# Обработка замечаний
1. get_task и история: прочитай все замечания и ответы. Используй receiving-code-review, проверяй обоснованность технически.
2. В роли ExecutorReply отвечай на вопросы; не меняй код. Для ответа submit_result outcome=completed; для встречного вопроса question. Сервис вернёт ход критику.
3. Изменения выполняются обычным исполнителем после возврата в To Do. Продолжай выделенные ветки и worktree, не создавай второй PR без причины.
4. Исправляй по пунктам; для несогласия приведи код, проверку или требование. Не соглашайся автоматически.
5. Если нужен человек, request_clarification. Разрешения внешних действий и навыков сохраняются.
6. Повтори затронутые проверки. В итоге перечисли исправленное, аргументированно отклонённое и непроверенное. Сохрани ссылки и артефакты.
