# Фронтенд от требований до проверки
1. Прочитай требования, инструкции репозитория, package/build-конфигурацию. Используй стек целевого проекта; vanilla JS обязателен только для самого Giga To Do.
2. Изучи макеты. Для Pixso используй pixso-design-reader и pixso-mockup-reader; соблюдай их ограничения. Не выдумывай содержание недоступного макета.
3. Определи команду запуска и порт из проекта/конфигурации задачи. Запусти локально с записью логов и явной проверкой готовности. Сохрани PID и останови только созданный тобой процесс после проверки.
4. Подключи API стенда штатной конфигурацией или dev-proxy. Для КСУП БИМ default: https://ksup-bim.ift.delta.sbrf.ru/bim/api. Это не default остальных проектов. Не дублируй /bim/api при сборке путей. Адрес переопределяемый.
5. Не коммить локальные настройки, cookies, токены и доступы. Не обходи TLS, CORS и ограничения доступа отключением защиты; используй предусмотренный проектом proxy. Если требуется доступ, запроси уточнение.
6. Захвати общий браузер инструментом acquire_resource resource=browser через MCP giga-todo. Если занят — запроси уточнение или заверши ход с блокировкой. Не вмешивайся в чужую сессию.
7. Через SberBrowser MCP devtools пройди согласованные сценарии: навигацию, формы, валидацию, загрузку, пустые состояния, ошибки, сохранение данных. Действия с данными стенда должны соответствовать поручению.
8. Проверь консоль и network: правильный backend, URL, метод, статус и ответ. Отличай ошибку UI от недоступного API.
9. Сравни композицию, отступы, размеры, типографику, состояния и нужные размеры экрана. Для Pixso не вызывай resize_page/emulate. Скриншоты с filePath, JPEG quality 70; большие snapshots тоже в файлы.
10. Исправь проблемы и повтори проверки. Сохрани отчёт: сценарий → ожидаемое → фактическое → итог, ссылки на дизайн, скриншоты и ограничения. Артефакты внутри общей папки задачи.
11. Освободи browser через release_resource и останови dev-сервер. Критик может независимо повторить сценарии. Не объявляй проверку успешной, если стенд/доступ/дизайн недоступны.
