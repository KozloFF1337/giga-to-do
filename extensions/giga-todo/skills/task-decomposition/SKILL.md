# Декомпозиция
1. Прочитай исходную задачу. Источники исследуй своими MCP; приложение не связано с конкретным трекером.
2. list_boards и при необходимости list_tasks/get_task. Доски analytics/frontend/backend/testing.
3. Каждая карточка содержит самостоятельный prompt: цель, контекст, ссылки, границы и критерии. Обязательно только prompt. Внешний source необязателен.
4. create_task может создавать карточки на любой доске. Стадию и позицию назначает сервер. Родитель и запуск сохраняются автоматически.
5. Один внешний тикет может иметь несколько разных работ. При повторном обнаружении не перефразируй прежнюю работу ради обхода дедупликации.
6. created=false означает, что карточка уже существует, включая Done. Сохрани возвращённый ID; не создавай копию другим текстом без новой реальной работы.
7. Если инструмент недоступен, не симулируй создание. Сохрани ошибку и уточнение. Созданные карточки не откатываются при ошибке родителя.
8. Итог родительской задачи: какие карточки созданы, найдены ранее, какие источники не удалось проверить.

Зависимости передавай в create_task как dependencyIds (UUID карточек, не внешние тикеты). Используй ID из list_tasks/get_task. Зависимости любых досок должны быть в Done; не создавай циклы. Новые задачи добавляются вниз, очередь выбирает сверху первую доступную. При дедупликации зависимости существующей задачи не заменяются автоматически.
