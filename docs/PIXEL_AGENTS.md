# React и Pixel Agents

## Источники

Используются Canvas 2D renderer, OfficeState, поиск путей, анимация персонажей/мебели и графика из https://github.com/pixel-agents-hq/pixel-agents.

Закреплённый commit: `b1bafd02896d90d83457266575a1e8e5011ce997`. Лицензия MIT: `frontend/vendor/pixel-agents/LICENSE`. Файлы upstream сохранены без изменения; `UPSTREAM.json` содержит SHA256 122 файлов. Проверка: `cd frontend && npm run check:vendor`.

Сервер Pixel Agents, запуск Claude, его hooks и сканирование transcript в приложение не включены. Агентов запускает существующий C#-диспетчер Gigacode.

## Файлы

- `frontend/src/App.jsx`: состояние приложения, четыре доски, SSE/polling, модальные окна.
- `Forms.jsx`, `TaskDetail.jsx`, `ui.jsx`: формы, зависимости, ревью, сообщения и история.
- `Office.jsx`: React-экран офиса, этажи, список и состояния загрузки/связи.
- `pixel-engine.ts`: адаптер оригинального движка; наш фиксированный layout на 20 рабочих мест, преобразование статусов и выбор задачи по персонажу.
- `office-model.js`: стабильное распределение по местам и отображение ролей/состояний.
- `scripts/build-pixel-assets.ts`: декодирование локальной PNG-графики оригинальными upstream-декодерами в JSON. В браузере нет внешних запросов к CDN.
- `src/GigaTodo/OfficeSnapshot.cs`: read-only проекция запусков, API `/api/office`.
- `src/GigaTodo/wwwroot`: результат production-сборки Vite. Исходники менять в frontend, не здесь.

## Контракт

SSE `refresh` раз в две секунды вызывает обновление snapshot. Есть запасной polling раз в пять секунд. Смена доски/закрытие страницы отменяет устаревшие запросы; перетаскивание не прерывается обновлением очереди.

`GET /api/office` отдаёт `at` и `agents`: id запуска, taskId, title, boardId, role, state, startedAt, finishedAt, runner, needsAttention, waitingForReview. Не отдаёт TokenHash, ProfileJson, pending result или CLI-транскрипт.

Все Running идут первыми, затем недавние завершённые за последние 45 секунд; максимум 120 записей. При конфигурационном максимуме 100 активных остаётся до 20 мест для недавних. Это ограничение снимка, а не новый лимит исполнения. Полная история всегда остаётся в карточке.

20 мест на этаж, до шести этажей для снимка из 120 запусков. Существующие места сохраняются при обновлении снимка. Новые запуски идут к столам; при открытии этажа уже работающие сразу находятся за своими компьютерами. У завершённых выключается компьютер, персонаж уходит в общий проход и позже исчезает из снимка. Критики читают, исполнители работают за компьютерами: это иллюстрация роли/статуса, а не доказательство конкретного вызова инструмента.

Вне связи анимация замораживается, UI показывает последнее известное состояние. Ошибка загрузки графики имеет кнопку повтора. Список персонажей — обычные кнопки, доступные с клавиатуры. Внутренние субагенты не создаются и не учитываются визуализацией.

## Сборка и развитие

`npm ci && npm run build` проверяет SHA256 vendor, генерирует графику, проверяет TypeScript и собирает frontend в wwwroot. Node нужен только при разработке/сборке; готовое приложение использует локальные файлы.

Для обновления upstream выберите конкретный commit, просмотрите изменения и лицензию, обновите используемый граф зависимостей TS/JSON и assets вместе, пересоздайте SHA256 manifest, затем выполните сборку, unit и browser-тесты. Не подменяйте vendor-файлы своими исправлениями без отдельного документированного patch; адаптация находится в `pixel-engine.ts`.

Чтобы показывать реальные tool-call события или внутренних помощников Gigacode, сначала подтвердите формат в целевом CLI. Затем нормализуйте события в сервисе/адаптере без разбора фиксированных названий внешних MCP. Нельзя выдавать текущую анимацию за подтверждённое отслеживание инструментов.
