# Зависимости и общий лимит

Актуальные правила заменяют прежний флаг последовательного выполнения.

- Новая карточка добавляется вниз To Do. Диспетчер просматривает колонку сверху вниз и выбирает первую доступную карточку. Незавершённые зависимости, пауза и ошибка не блокируют следующие карточки.
- Задача запускается только после Done **всех** зависимостей. In Work и In Review недостаточно. Ссылаться можно на задачи любой доски.
- Зависимости задаются при создании, для To Do их можно изменить в окне задачи. Самоссылки, отсутствующие задачи и циклы запрещены; конкурентные изменения графа сериализуются в PostgreSQL.
- Повторы сохраняют фиксированный набор ID зависимостей; каждый экземпляр ждёт эти задачи, а не предыдущий экземпляр расписания.
- Дедупликация по описанию/источнику сохраняется: повторное создание не заменяет зависимости существующей карточки.
- Общий потолок — **Runtime__MaxConcurrentAgents**, целое число от 1 до 100, по умолчанию 10 активных запусков приложения на все доски: исполнители, критики и ответы исполнителя. Дочерние агенты внутри Gigacode отдельно не считаются. Сохранённый, но ещё не применённый итог занимает слот до выхода процесса.
- Настройки отдельных досок действуют внутри общего потолка. Атомарный подсчёт и назначение защищены общей PostgreSQL advisory transaction lock.

## API
`POST /api/tasks` и `POST/PUT /api/schedules` принимают необязательный `dependencyIds: [UUID, ...]` вместо `sequential`. MCP create_task использует то же поле.

`POST /api/tasks/{id}/dependencies`: `{ "version": 7, "dependencyIds": ["..."] }`. Менять можно только To Do без активного запуска; устаревшая версия даёт 409.

`GET /api/task-options` возвращает ID, название, доску и стадию для выбора. `GET /api/runtime` включает `activeAgents` и `agentLimit`.

## Миграция
TaskDependencies удаляет старые Sequential/BarrierTaskId и добавляет массивы DependencyIds. У существующих задач и шаблонов зависимости изначально пустые: старый флаг не преобразуется в выдуманные связи. Видимый порядок карточек сохраняется, но теперь верхняя имеет приоритет. Перед включением исполнения настройте нужные связи. Миграции применяются при старте приложения; прежние миграции сохранены для обновления существующей базы.
